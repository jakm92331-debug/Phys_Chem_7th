# منطقة المعلّم: النشر، المصادقة، ومساحة استقبال الحلول

منطقة المعلّم في هذه المنصة ليست واجهة عادية: هي **مساحة محمية بمصادقة حقيقية
من جهة الخادم**، وجميع بياناتها (حلول الدروس) لا تصل إلى أي زائر قبل تسجيل الدخول.
هذا المستند يشرح كيف تُنشر، وكيف تتم إدارة الحلول، ولماذا لا تعمل على الاستضافة
الثابتة.

## لماذا لا تعمل المنطقة على GitHub Pages

المنصة تُنشر حالياً كحزمة ثابتة (SPA) على GitHub Pages. الاستضافة الثابتة لا
تستطيع تنفيذ أي منطقة خادم — لا يمكنها التحقق من كلمة مرور أو الاحتفاظ بجلسات.
لذلك، وعلى المضيف الثابت، تُعرض منطقة المعلّم **حالة صريحة توضّح أن خادم
المصادقة غير متوفّر**، ولا يوجد أي شكل من أشكال الحماية. هذا ليس ضعفاً
طارئاً: هو قرار مصمم عمداً ليكون واضحاً. **لا تعتبر منطقة المعلّم محمية إلا
عندما يُشغَّل الخادم الخلفي المصاحب على مضيف يدعم Node.js.**

لا تحتوي حزمة الطالب على أي بيانات معلّم: لا حلول، ولا عناوين دروس خاصة، ولا
معرّفات داخلية. بنية الحلول موجودة في واجهة المعلّم فقط بعد تسجيل الدخول،
وحتى رموز الفئات في CSS لا تكشف أي محتوى.

## نشر الخادم المصاحب

يتكون الخادم من ملفات Node.js خالصة (لا تجميع):

```
server/index.js      المدخل: التحقق من كلمة المرور، ثم الاستماع
server/app.js        الموجز: معالجة الطلبات (API + ملفات ثابتة)
server/auth.js       المصادقة: scrypt، الجلسات، معدل محاولة الدخول
server/store.js      مستودع الحلول على ملف JSON
scripts/hash-password.mjs    توليد hash كلمة المرور
scripts/build-teacher-solutions.mjs  بناء ملف الحلول من ملف الاستقبال
```

### 1. توليد hash كلمة المرور

```bash
npm run hash:password
```

يُطلب إدخال كلمة المرور (لا تُعرض، ولا تُحفَظ في أي ملف). الناتج سطر واحد من
الشكل `scrypt$16384$8$1$<salt>$<hash>`.

> **كلمة المرور أو الhash لا يدخلان المستودع أبداً.** احفظ الhash كسر
> (secret) في بيئة النشر، واستخدم المتغير `TEACHER_PASSWORD_HASH`.

### 2. تشغيل الخادم

```bash
TEACHER_PASSWORD_HASH='scrypt$16384$8$1$...' node server/index.js
```

متغيرات البيئة:

| المتغير | القيمة | الوصف |
|---|---|---|
| `TEACHER_PASSWORD_HASH` | مطلوب | hash scrypt للكلمة الابتدائية. يرفض الخادم البدء بدونها أو بصيغة غير صحيحة. |
| `PORT` | `8787` | منفذ الاستماع. |
| `TEACHER_DATA_DIR` | `server/data` | مكان ملف `teacher-solutions.json`. |
| `TEACHER_DIST_DIR` | `dist` | مكان الحزمة الثابتة المُقدَّمة. |
| `TEACHER_SECURE_COOKIES` | `false` | `true` يضمن `Secure` على الكوكيز (لل HTTPS فقط). |

يبدأ الخادم على `0.0.0.0:8787`، ويخدم:

- `GET /api/teacher/health` — فحص الصحة (لا يحتاج مصادقة).
- `POST /api/teacher/login` — المصادقة (محدودة بـ 5 محاولات خاطئة لكل عنوان IP
  خلال 15 دقيقة).
- `POST /api/teacher/logout` — إلغاء الجلسة.
- `GET /api/teacher/session` — حالة الجلسة الحالية.
- `GET /api/teacher/solutions` — بيانات الحلول (تتطلب جلسة صالحة).
- `POST/DELETE /api/teacher/solutions/:entryId` — كتابة/حذف مجموعة حلول
  درس واحد (تتطلب جلسة + تطابق المعرّف).
- كل شيء آخر — الحزمة الثابتة للطالب (مع الـ SPA fallback وheaders أمنية).

### 3. تمكين المصادقة في بيئة التطوير

في `vite.config.ts`، يُوجَّه `/api/teacher/*` إلى `http://localhost:8787` (يمكن
تجاوزه بـ `TEACHER_SERVER_URL`). ابدأ الخادم أولاً ثم `npm run dev`: عندها تظهر
واجهة المعلّم بنظام دخول حقيقي.

## مساحة استقبال الحلول (Solution Intake)

المعلّم يملأ حلول الدروس في ملف JSON واحد:

```bash
cp teacher-solutions.intake.example.json teacher-solutions.intake.json
```

كل درس له «قالب» من الفتحات: لكل صفحة سؤال، ولكل عائلة أسئلة (أسئلة الفهم،
التمارين، المسائل). كل فتحة تحتوي على بنية الحل الكامل:

- نص السؤال (`prompt`)
- الإجابة الصحيحة (`answer`)
- خطوات الحل (`steps`)
- القوانين المستعملة (`lawsUsed`)
- سبب اختيار الطريقة (`methodReasoning`)
- التعويضات والوحدات (`substitutions`)
- رقم صفحة السؤال في الكتاب (`pageRef`)

القالب يُنشأ برمجياً عبر `createEntryTemplate` في
`src/lib/solution-intake.ts`؛ والبنية المرجعية المفصلة توجد في
`SAMPLE_INTAKE_DATA` في نفس الملف (توضيحية، ولا تُدمج في حزمة الطالب).
بعد ملء الحلول:

```bash
node scripts/build-teacher-solutions.mjs
```

يُتحقق من الملف (بنفس القواعد البنائية التي يطبقها الخادم)، ويُكتب
`server/data/teacher-solutions.json` مع ختم `updatedAt`. لا تُحشى الحلول أمثلة
وهمية: الحلول تُضاف فقط بعد مراجعة صفحات الكتاب المعتمدة.

## الخصائص الأمنية

- **المصادقة**: `scrypt` (N=16384) مع salt عشوائي لكل كلمة مرور، والتحقق
  بزمن ثابت (`timingSafeEqual`). لا توجد كلمة مرور نصية في أي ملف من المستودع.
- **الجلسات**: معرّفات عشوائية 256-بت، لمدة 12 ساعة، على الخادم فقط ( restart
  يُلغيها). الكوكيز `HttpOnly` + `SameSite=Strict`.
- **معدل المحاولة**: 5 فشلات لكل IP خلال 15 دقيقة، ثم حظر مؤقت (429).
- **البيانات**: الحلول على الخادم فقط. لا توجد حلول في الحزمة المرسلة إلى
  المتصفح، ولا يمكن الوصول إلى ملف البيانات عبر مسارات ثابتة
  (يُحجب التجاوز عبر `..` والتشفير `%2f`).
- **فحص الأسرار**: مجموعة اختبارات الخادم تفحص المستودع بجميع أشكاله، وتفشل
  إذا وُجدت كلمة المرور أو hashها في أي ملف.

## الاختبارات

```bash
npm test              # واجهة الطالب (vitest): 191 اختبار
npm run test:server   # خادم المعلّم (node:test): 20 اختبار، يشمل فحص الأسرار
```

الاختبار النهاائي (e2e) يُشغِّل الخادم الحقيقي + vite الحقيقي + Chromium،
ويتحقق من: تجربة الطالب لا تتأثر، رفض كلمة المرور الخاطئة، الدخول الحقيقي،
عرض الحل من الخادم، وتسجيل الخروج:

```bash
# Chromium مطلوب (مثال: من حزمة @sparticuz/chromium):
CHROMIUM_PATH=/path/to/chromium \
CHROMIUM_LIBS=/path/to/shared-libs \
node e2e/teacher-flow.mjs
```

`CHROMIUM_LIBS` توجِّه `LD_LIBRARY_PATH` لل libraries المشتركة التي تحتاجها
Chromium عند استخراجها من حزمة مستقلة (وهي الحالة المعتادة خارج أنظمة
Linux الكاملة).
